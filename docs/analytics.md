# Статистика 1+2=3

## Состояние подключения

Сбор включён для публичного сайта: владелец предоставил публичный токен проекта PostHog EU. `analytics-config.mjs` содержит `enabled: true`. События отправляются с новых загрузок страницы после публикации. Исторические посещения до включения восстановить нельзя.

28 сентября 2026 проверены CORS для `https://duman-sadu.github.io` и приём события: API вернул HTTP 200, `status: Ok`. Проверочное событие называется `analytics_connection_check`, использует `app: bir-eki-ush-setup` и не входит в игровые отчёты. Приём API не заменяет проверку появления событий в кабинете владельца.

Доступ к управлению PostHog пока не предоставлен: отдельный кабинет с отчётами ещё не создан, настройки доступа проекта и отбрасывания IP на стороне сервиса не проверены. Публичный ключ разрешает только отправку событий. Владелец может смотреть события через свой аккаунт на https://eu.posthog.com/ (Product analytics / Activity).

## Подключение владельцем

1. Установить и подключить PostHog в Codex. Использовать отдельный проект для этой игры.
2. Получить из проекта публичный Project token (`phc_…`) и регион EU/US. Включить в настройках проекта Discard client IP data. Не включать запись сессий и автоматический сбор форм.
3. Создать кабинет «1+2=3 — Статистика» в PostHog по спецификации ниже. Доступ — только через аккаунт владельца; не включать публичное sharing. Если проект командный, проверить доступ участников.
4. В `analytics-config.mjs` указать только публичный токен приёма событий и `apiHost`. Личные API-ключи, пароли и токены чтения в игру или GitHub не помещать.
5. Включить `enabled`, опубликовать. Проверить настоящую сессию на публичном сайте: открытие, старт, проигрыш, WhatsApp. Убедиться в поступлении событий и в отсутствии имён/URL вызовов.
6. Проверить, что кабинет требует входа в аккаунт, и передать владельцу его ссылку.

Игра работает независимо от аналитики. Если PostHog недоступен, заблокирован или не настроен, игра продолжает работать. На localhost сбор выключен.

## Показатели кабинета

Все отчёты фильтруются по `properties.app = bir-eki-ush`, периоды — день, 7 и 30 дней. Часовой пояс кабинета: Asia/Qyzylorda.

| Отчёт | Событие / расчёт |
| --- | --- |
| Открытия игры | Число `page_view` |
| Посетители | Уникальные `distinct_id` в `page_view` |
| Нажали «Бастау» | Число `start_clicked` |
| Начатые партии | Число `game_started` (после отсчёта) |
| Игроки | Уникальные `distinct_id` в `game_started` |
| Завершённые партии | Число `game_finished` |
| Результаты | Среднее/максимум `score`, распределение `level` в `game_finished` |
| Причины проигрыша | `game_finished` с разбивкой `reason`: wrong / timeout |
| Вернувшиеся посетители | Уникальные `distinct_id` в `page_view` с `returning_visitor = true` |
| Переходы к WhatsApp | Число `share_clicked` — нажатия, не подтверждённые отправки |
| Пришли по вызову друга | Уникальные `distinct_id` в `page_view` с `challenge = true` |
| Средняя длительность партии | Среднее `duration_ms` у `game_finished`, без стартового отсчёта |

Конверсия открытия в игру: уникальные игроки / уникальные посетители за один период. Закрытые вкладки во время игры не считаются завершёнными партиями; отсутствие финиша нельзя автоматически считать проигрышем. Начало и конец партии связываются по `round_id`.

## Какие данные передаются

Случайный идентификатор браузера, тип события, время, числовые показатели партии, причина проигрыша и признаки вызова друга. Имена, тексты форм, URL с именами друзей, реферер и запись экрана не отправляются. По событиям не создаются именные профили. В свойствах обнуляется IP и отключается GeoIP; сетевое соединение всё равно проходит через сервер провайдера.

Идентификатор хранится в localStorage до 90 дней. Возврат означает посещение спустя минимум 24 часа после первого открытия. При очистке хранилища, приватном режиме или смене устройства человек может считаться новым посетителем. DNT/GPC отключают сбор. Показатели приблизительные: блокировщики и потеря сети уменьшают число зарегистрированных событий.
